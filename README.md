# URBAN PULSE

**Bengaluru Urban Mobility and Road Safety Intelligence Platform**

URBAN PULSE is a Big Data Analytics project for organizing historical traffic and road-safety data into an analytics workflow and dashboard. The repository includes Python data-processing and analytics scripts, a FastAPI backend, and a React frontend.

> **Data integrity:** Historical crash analysis is based on recorded historical data. The Predictive Insights page's forecasts, risk scores, model metrics, and recommendations are illustrative; no trained predictive model is connected. Live Monitoring events and their map coordinates are simulated and are not real-time traffic observations.

## Project objectives

- Clean and validate available road-safety and traffic datasets while retaining missing values.
- Produce year, category, station, and hotspot summaries with PySpark and save analytics as Parquet.
- Serve prepared analytics through a FastAPI API.
- Present historical data and clearly labelled illustrative content in a Bengaluru-focused dashboard.

## Dashboard pages

| Page | Implemented content | Data distinction |
|---|---|---|
| **Overview** | Dashboard summary, annual accident chart, violation mix, alerts, and data status | Annual accident chart uses the accident API. Several summary metrics, violation mix, alerts, and pipeline status are illustrative. |
| **Accident Intelligence** | Year and zone filters, crash trends, station and zone summaries, and hotspot information | Uses historical accident APIs. Current crash analysis covers 2023–2025. |
| **Violation Analytics** | Motor Vehicle Act annual summaries and offence rankings, with filters and charts | Yearly and top-offence data are API-backed. The area comparison remains illustrative. |
| **Predictive Insights** | Historical crash hotspots, increasing station trends, fatality percentages, and separate forecast/demo panels | Historical Crash Intelligence is backend analysis for 2023–2025, not a forecast. Forecasts, risk scores, rankings in the demo panel, model metrics, and recommendations are illustrative. No trained ML model is connected. |
| **Live Monitoring** | Event feed, filters, event details, map, and activity chart | Events are generated by a simulator and held in an in-memory backend store. Map coordinates are illustrative, not live incident locations. The store is limited to 60 events and is reset when the backend process restarts. |

## Data and processing workflow

The local raw inputs currently include:

- `data/raw/road_crashes/` CSV files with names indicating coverage from 2007 through 2025, plus year/range-specific files.
- `data/raw/motor_vehicle_act_cases.csv`
- `data/raw/drink_and_drive_cases.csv`
- `data/raw/traffic_cases_and_fines.csv`

The raw CSV datasets must be obtained separately; the repository does not contain them. Processing scripts clean and validate those inputs, then analytics scripts create cleaned datasets and Parquet outputs under `data/processed/`. For crash analytics, `src/urban_pulse/processing/clean_crash_data.py` combines the 2023, 2024, and 2025 station files into the intermediate `data/processed/crash_records_2023_2025.csv`; `src/urban_pulse/processing/spark_crash_analysis.py` reads that intermediate file to produce crash analytics. Crash analytics include yearly, zone, station, hotspot, and station-trend outputs. Violation analytics cover Motor Vehicle Act offences, drink-and-drive cases, and traffic cases/fines.

Raw data and processed files are excluded from Git by `.gitignore`. Obtain the raw inputs separately, then generate cleaned datasets and Parquet outputs locally by running the appropriate processing and analytics scripts. The repository does not include a single pipeline runner or documented source-data download procedure. Dataset publishers, provenance, and reuse licenses have not been identified in the repository; consult the original data provider before redistribution.

## Setup and run locally

### Prerequisites

- Windows PowerShell instructions are shown below; adapt activation commands for other operating systems.
- Python 3.11.
- Node.js and npm. Exact required versions are not documented; validate them on a clean machine.
- A Java installation compatible with the installed PySpark release is needed for local Spark jobs. The required Java version has not been documented or clean-machine validated.
- The raw inputs and generated Parquet files required by the APIs. They are not included in Git.

### Backend

From the project root, create/activate the project environment and install Python requirements:

```powershell
python -m venv urban_env
.\urban_env\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Then, from the project root `E:\urban-pulse`, start the backend:

```powershell
uvicorn backend.app.main:app --reload
```

The API listens on `http://127.0.0.1:8000` by default. This launch command has not been validated on a clean machine. Analytics routes require their corresponding files under `data/processed/analytics/`; missing files cause the API to return an error.

### Frontend

In a separate terminal:

```powershell
cd frontend
npm install
npm run dev
```

Vite's configured development server is used. The frontend API client reads `VITE_API_BASE_URL` and defaults to `http://127.0.0.1:8000`. To configure it locally, set this variable in `frontend/.env`:

```dotenv
VITE_API_BASE_URL=http://127.0.0.1:8000
```

The local `.env` file is ignored by Git. The backend CORS configuration currently permits `http://localhost:5173` and `http://127.0.0.1:5173`.

### Frontend build and lint

Run these from `frontend/`:

```powershell
npm run build
npm run lint
```

These scripts are defined in `frontend/package.json`. No frontend test script is currently defined.

## Testing

Start the backend and ensure the required analytics Parquet files are available, then run from the project root in an activated Python environment:

```powershell
python tests/check_api_endpoints.py
```

This script checks the health route, expected API response counts, overview data, historical insights, and live event feed behavior. It also sends a POST request to generate a simulated event. It is an API check script, not a pytest suite. The expected counts depend on the corresponding datasets and analytics outputs being present. There is no frontend test command configured.

## Data quality and limitations

- The Motor Vehicle Act cleaned dataset contains 320 rows for 2018–2025 and 29 missing case values. Missing values are retained, not interpreted as zero.
- The drink-and-drive dataset has 12 months each for 2016–2018, but only January and February are reported for 2018. The 2018 annual total is partial and should not be directly compared with complete years.
- Traffic cases/fines include four K.T.C. Act records with missing cases and fines. Validation also identifies a 22-case difference in 2022 between available category sums and the source-reported annual total; the reported annual total is preserved.
- Historical Crash Intelligence summarizes recorded crash analysis for 2023–2025. It does not produce future predictions or causal conclusions.
- Predictive Insights forecasts, risk scores, model metrics, and recommendations are illustrative UI content. No trained predictive model is connected.
- Live Monitoring uses random backend-generated events and illustrative map coordinates, not actual traffic, incident, or sensor feeds.
- API data access depends on local Parquet outputs that are not tracked in this repository. Without those files, relevant routes cannot serve analytics.
- Although weather is part of the broader project goal, the inspected repository contains no weather dataset, processing pipeline, or API integration.
- Dataset source attribution and licensing, compatible Java and Node/npm versions, and clean-machine setup have not yet been confirmed.
